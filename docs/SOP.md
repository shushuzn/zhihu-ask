# 知乎深度回答项目 — 可执行 SOP

本文档是流程标准。任意知乎问题都按这五个阶段执行；执行时可参考模板（见 `templates/`）。

## 阶段 0 · 问题分析与范围界定

1. 拆解问题：主概念、关键实体、隐含前提、真实诉求（科普/建议/案例）。
2. 判定查询类型：
   - 深度优先 — 单一议题需多角度剖析 → 3–5 个子代理按视角分工。
   - 广度优先 — 含多个独立子议题 → 每个子议题一个子代理。
   - 直接查询 — 事实速查 → 1 个子代理 + 主代理。
3. 定目标读者与篇幅：知乎主流用户，正文推荐 800–3000 字 + 必要数据。
4. 落盘：在 `research/<topic_slug>/plan.md` 完成问题界定、关键词表、子代理分工。

## 阶段 1 · 信息检索（三通道）

通道 A：微信公众号检索（必用）
- 加载 `wechat-article-search` skill。
- 必须带时间参数，默认近 1 年（如 2025-08 至 2026-08）。
- 关键词组合「主题词 + 视角词」，单题准备 6–12 组，可迭代增补。
- 本机 PowerShell 下命令行中文参数会乱码，改用项目工具 `tools/wechat_search.py`（见 `docs/TOOLS.md`）：将关键词写入 UTF-8 的 `tools/keywords.json`，再执行 `python tools/wechat_search.py --keywords tools/keywords.json --time-range <起> <止>`。

通道 B：Web 检索与抓取
- `web_search` / `web_fetch` 获取官方数据、研报、新闻、论文，用于事实核查。
- 优先原始来源（官方发布、权威机构）而非聚合站。

通道 C：插件领域工作流
- 金融问题 → finance 插件（测算、报表、归因）。
- 产品问题 → product-management 插件（对比矩阵、PRD、竞争分析）。
- AI/工具问题 → 以通道 A、B 为主。

合成原则：公众号负责深度观点与实操经验，Web 负责事实与数据背书，插件负责领域分析输出；三方交叉印证。

## 阶段 2 · 信息收集与多视角研究

**实际执行方式（默认）：主代理直接执行，不使用子代理。** 因 `research_subagent` 配置的模型不可用（"Model not found"），本项目实际运行中由主代理用 web_search / web_fetch 直接完成全部检索。已实测可行（前两份研究均以此方式完成）。

主代理按以下五视角分工逐项收集，确保覆盖度：

| 视角 | 收集内容 | 工具 |
|---|---|---|
| A 公众号内容 | 观点、实操、案例 | tools/wechat_search.py |
| B Web 事实 | 官方数据、研报、新闻 | web_search / web_fetch |
| C 领域分析 | 金融测算 / 产品对比 | finance / product-management 技能 |
| D 差异化 | 既有高赞回答与争议观点 | web_search |
| E 反方风险 | 质疑、失败案例、风险提示 | web_search |

执行要点：
- 每个视角至少一轮检索；关键子问题（见阶段 0 界定）逐一覆盖，不遗漏。
- 检索时优先一手来源；媒体转述数字记入"待回溯"清单，进入阶段 3 核实。
- 若未来 `research_subagent` 配置修复可用，可改为并行分派（参考 `docs/AGENT_PROMPTS.md` 模板），但当前以主代理直执为准。

## 阶段 3 · 交叉验证与量化

- 每个关键数字标注数据级别（一手/二手/推断）；多源冲突以「最新 + 一手优先 + 口径一致」取舍。
- 对媒体转述的数字，尽量回溯到一手来源（官方公告、论文、财报、交易所数据）；无法取得的一律标注"仅媒体口径"。
- 做至少一项量化测算（市场规模/成本结构/情景推演），把模糊判断变成数字。
- 检查覆盖缺口：利益相关方是否都覆盖、有无对标、风险矩阵是否完整。
- 边际收益下降即停止，避免资源浪费。

## 阶段 4 · 报告与回答生成

- 按智库级 `templates/research_report_TEMPLATE.md` 产出 `research/<topic_slug>/report.md`（含量化测算、多维分析、对标、风险矩阵）。
- 按 `templates/zhihu_answer_TEMPLATE.md` 产出 `zhihu_answer.md`（文风见 `docs/STYLE_GUIDE.md`，必须通过模板内置的「去 AI 味自查」；关键数字需与报告一致并嵌进叙述）。
- 写 `process_notes.md` 沉淀：本次有效关键词、踩坑点、可复用结论。
- 回填本地 `plan.md` 问题索引状态（进行中/已完成）。

## 质量红线

- 所有可量化数据必须有来源；无法核实的标注「未证实」。
- 不编造引用、不虚构数字、不替用户做决定（给权衡，不给单一路径）。
- 引用公众号文章须保留标题与作者信息。
- 回答须像真实从业者所写，无 AI 模板腔（框架词/排比句/对称观点），按 `docs/STYLE_GUIDE.md`「去 AI 味」自查后发布。
