# 知乎深度回答项目 — 完整流程 SOP

本文档定义知乎问题从接收、研究、产出到沉淀的完整流程标准，覆盖执行者职责、流转规则、异常处理、数据格式、决策点、时限、告警与闭环追溯。流程分五个阶段执行，模板见 `templates/`，工具见 `tools/` 与 `docs/TOOLS.md`，环境约定见 `docs/CONVENTIONS.md`。

## 0. 角色与职责总表

| 角色 | 职责 | 不可替代动作 |
|---|---|---|
| 用户（提问者） | 提供问题内容；审批关键决策点；验收最终交付物 | 问题来源、发布决定 |
| 主代理（执行者） | 全流程执行：检索、核查、测算、写作 | 所有研究与写作 |
| research_subagent | 预留并行研究角色（当前不可用，见阶段 2） | — |
| 健康检查工具 | 会话启动/排障时校验环境就绪 | health_check.py |
| pre-commit hook | 提交前拦截内部文件误入库 | 自动化校验 |

**职责边界**：研究执行、事实核查、报告写作由主代理全权负责；涉及"是否发布""是否删除内容""是否强推/改可见性"等必须由用户明确审批，主代理不得代替用户决策。

## 阶段 0 · 问题接收与范围界定

**执行者**：主代理（需用户提供问题内容）；**输入**：用户问题（标题/描述/链接）；**输出**：`research/<slug>/plan.md` 问题界定完成。

步骤：
1. 接收问题。若为知乎链接，先尝试 web_fetch 抓取；失败（403/登录墙）则请用户粘贴标题或描述。
2. 拆解问题：主概念、关键实体、隐含前提、真实诉求（科普/建议/案例）；同时评估**阅读价值**：本角度对知乎读者的增量信息与反常识点（数据反差、口径之争、反常识事实）——角度平淡时优先切入更有传播性的子角度，阅读量取决于"读者 3 秒能抓住的增量"。
3. 判定查询类型：
   - 深度优先 — 单一议题需多角度剖析 → 五视角逐项覆盖（阶段 2）。
   - 广度优先 — 含多个独立子议题 → 每个子议题按五视角覆盖。
   - 直接查询 — 事实速查 → 一轮检索即可。
4. 定目标读者与篇幅：知乎主流用户，正文 800–3000 字 + 必要数据。
5. 初始化：写 `tools/start.json`，执行 `python tools/research_start.py --config tools/start.json`（自动初始化目录 + 公众号检索 + 素材库落盘）。

**流转条件**：plan.md 问题界定完成（主概念/诉求/读者/关键词齐备）→ 进入阶段 1。
**时限**：0.5 小时内完成。

## 阶段 1 · 信息检索（多通道：F 查重 + E/A/B/C）

**执行者**：主代理（直执）；**输入**：plan.md 关键词表；**输出**：`gathered_wechat.md` 素材库 + `gathered_ima.md` 素材库 + Web 检索记录。

**执行顺序**：F（flomo 查重）→ E → A → B → C → P（步骤 0 查重最先：确认是否已有本主题笔记，避免重复新建；随后通道 E 查历史经验，为关键词与后续通道定基调；P 学术预印本聚合涵盖全部预印本——arxiv 与 bioRxiv/浪淘沙/PSSXiv 一并检索，覆盖理工/生物医学/中文交叉/哲学社科领域）。

步骤 0 · flomo 已有笔记查重（P0 · 执行顺序最先）：
- 用问题主题词（从 plan.md/start.json 的 question 取，主代理判断，不自动提取）调 flomo MCP `memo_search`，查是否已有本主题高相关笔记。
- 决策规则（relevance 取最相似笔记）：
  - `relevance ≥ 0.9`（已有本主题笔记）→ **不重复新建**：复用已有笔记（本地 research/ 有同名目录则直接更新增量），跳过检索通道或仅补缺口；本地目录缺失时，从 flomo 用 `memo_batch_get` 拉取命中笔记全文，在其基础上**只补新信息**，不重建目录。
  - **旧笔记过时信息更新（命中时必做）**：新信息推翻旧笔记表述时（"尚无定论""待观察""未发布"等被证实/证伪），旧笔记中过时句子必须原地更新（补结局或改写），不得只新增笔记而让旧笔记与新笔记自相矛盾；更新后的旧笔记与新增笔记一并质检上传。
  - `0.5 ≤ relevance < 0.9`（主题相近，如单论点笔记/其他笔记）→ 正常开展检索通道（flomo 条目按「flomo 笔记素材引用规则」判断可用性：有合规 GB/T 7714 参考文献即可作素材）。
  - `relevance < 0.5`（无重叠）→ 正常开展检索通道。
- 查重结果记录到 plan.md（如"flomo 已有笔记：无 / 相近（id=xxx）"）。
- **查重与素材边界**：flomo 查重用于"是否已有本主题笔记"的判重；命中的 flomo 条目（信号笔记/趋势笔记/其他笔记）**可作参考素材，但须符合「flomo 笔记素材引用规则」**——有符合 GB/T 7714-2015 的参考文献才可用；参考文献不合规或没有 → 联网找对应来源；找不到 → 该笔记不可用。检测 `python tools/check_flomo_note_refs.py --keywords "<主题词>"`。
- 前置：flomo MCP 已在 WorkBuddy 连接器管理中配置；未配置或调用失败时**阻断**，禁止进入后续通道。查重与上传共用同一工具链，上传前仍按 流程再查重一次（防并发新增）。
- **笔记上传规则**：
  1. 索引笔记(00_index.md)和报告(report.md/report_draft.md)禁止上传 flomo
  2. 笔记上传前必须跑质检: `python tools/quality_check.py --file notes/xx.md`, 通过后再上传
  3. 每条笔记单独质检, 通过后逐条上传
- **flomo 笔记素材引用规则**：flomo 检索命中的笔记若用作参考素材，**必须有符合 GB/T 7714-2015 的参考文献**——有参考文献但不合规（缺类型标识/URL 缺引用日期/编号不连续）同样**不可用**；没有参考文献就联网（ddgs）找对应参考文献，网上也找不到则该笔记**不可用**（不得引用）。检测用 `python tools/check_flomo_note_refs.py --keywords "<主题词>"`（或 --file/--dir）；输出状态：✅可用（含合规参考文献）/ 🔎待确认（无参考文献但联网有相关候选，需人工确认对应性）/ ⚠️重试（联网搜索失败）/ ❌不可用（无参考文献且联网无对应来源，或参考文献不合国标）。

通道 E（ima 知识内容，P1 · 可用时必用 · 执行顺序第一；连接器未配置时由初始化**环境级自动登记 skip**，无需逐篇手动检查，连接器接入后自动失效并改为手动登记）：两级检索——
- **E1 经验检索**：`search_knowledge_base` 定位相关库 → 对个人库/项目沉淀 `search_knowledge`，命中片段（历史经验/词库/报告要点）纳入检索起点，与 `tools/rag_search.py`（SQLite BM25）本地检索互补。
- **E2 内容素材检索**（核心）：按问题领域从 `docs/IMA_LIBRARIES.md` 选取候选订阅库（研报/公告/论文/法规等 50+ 库），**对该领域全部候选库逐个 `search_knowledge` 检索**，命中内容（标题/摘要/命中片段/时间）落盘 `research/<slug>/gathered_ima.md` 素材库（条目含 库名/标题/类型/media_id，可追溯），与通道 A/B/C 并列计入有效通道数；阶段 3 需原文时 `fetch_media_content(media_id)` 读取。
- **E2 执行纪律**：候选库必须按领域取全（如数码/消费电子 → 电子行业研究库 + 明星科技公司财报库，不只查一个"最全研报库"）；每库至少换 2 个不同关键词（主概念+视角词，如"手机 销量"→"iPhone 中国 份额"）；**全部候选库、全部关键词均无命中才可记录"通道 E 无有效素材"**；禁止只查 1 个库、1 个关键词即放弃。

前置：ima 连接器已授权（侧边栏「更多 → ima知识库」）；未连接时跳过，不阻塞其余通道。隐私边界见 `docs/CONVENTIONS.md` 第 7 节（读取无限制，写入仅公开级内容）。
通道 A（公众号，优先级按领域：财经时政 P0 / 科技产业 P1 / 学术科研 P2）：经 `tools/wechat_search.py`（UTF-8 文件传参规避乱码）检索，带时间参数（默认近 1 年），`--output` 落盘素材库。**降级**：`sogou_search.py` 缺失时脚本自动降级为 ddgs 检索 `site:mp.weixin.qq.com`（抓取补标题/公众号名），无需安装。
通道 B（Web，P0 · 不分主题）：`web_search`/`web_fetch` 获取官方数据、研报、新闻，优先一手来源；脚本 `tools/web_search.py --out research/<slug>/gathered_web.md` 落盘即**自动登记通道 B**（done/empty 按命中数，同 A/P 通道惯例）。**降级**：`web_search` 工具不可用（HTTP 402 会员权益验证失败）时，改用 `tools/web_search.py`（ddgs 元搜索，无需 API key，`--out` 落盘）检索；仍失败再走 `web_fetch` 直抓已知站点。
通道 C（领域能力：插件/连接器；优先级按领域：科技产业/财经时政 P0、学术科研 P1——**通达信 `tdx-connector`、企查查 `qcc-company`、智慧芽 `patsnap-search` 为对应领域必做**）：按问题类型选数据源——**必做项（按领域）**：通达信（A股/港股/美股/期货期权行情、K线、F10 深度财务 30 接口、条件选股、宏观/新闻/公告/研报检索，code 先 `tdx_lookup_stock` 查码）、企查查（企业工商登记/股东/实控人穿透/财务/上市信息，先 `get_company_by_query` 锁定实体，多候选须用户确认）、智慧芽（专利/学术论文检索与全文：keyword 精确词 / semantic 技术问题语义检索 / filter 申请人·发明人·IPC·日期·法律状态·被引过滤，专利与论文各一次调用，`patsnap_fetch` 按公开号/URL 取 Markdown 全文；无命中记录"通道 C 智慧芽无有效素材"）；**按需项**：finance 插件（财务建模/报表分析）。连接器未配置时记 skip 并在 note 说明。工具用法与纪律见 `docs/TOOLS.md`「领域连接器」章节。
arxiv 平台由 `tools/arxiv_search.py` 单独检索（标题/作者/日期/摘要/arxiv 链接/PDF），落盘 `research/<slug>/gathered_arxiv.md`，自动登记通道 P；日常推荐用统一入口 `tools/preprint_search.py --platform all`。**网络限制（重要）**：本环境命令行 `curl` 无外网出口，`search_arxiv.sh`（curl 实现）永远空返回；Python `urllib` 经 `HTTPS_PROXY` 可联网，但 ArXiv API 对本机代理 IP 频繁限流（HTTP 429），故 `--query` 直连不稳定。无命中时优先走 WebFetch 降级：先 `--query "..." --print-web-prompt` 打印 URL 与 prompt，由 agent 用 **WebFetch 工具**（走 WorkBuddy 后端代理，可联网）抓取并保存响应为 `arxiv_raw.txt`，再 `tools/arxiv_search.py --raw arxiv_raw.txt --out gathered_arxiv.md` 解析落盘（支持 Atom XML 与分隔符文本两种输入）。工具用法见 `docs/TOOLS.md`「arxiv-watcher」章节。

通道 P（学术预印本聚合，优先级按领域：学术科研 P0 / 科技产业 P2 / 财经时政 P2）：用 `tools/preprint_search.py --platform all --keywords "<主题词>" --days 30 --count 5 --out research/<slug> --slug <slug>` 一次检索四平台——**arxiv**（复用 arxiv_search）、**bioRxiv**（生物医学，公开 REST API，分页+重试）、**浪淘沙**（LangTaoSha，中文跨学科，OJS 3.5 Atom feed 本地过滤）、**PSSXiv 哲学社会科学预印本**（中国人民大学复印报刊资料运营，POST 搜索解析编号/标题/摘要）。落盘分流：arxiv → `gathered_arxiv.md`；其余三平台 → `gathered_preprints.md`；两文件同属通道 P，检索完成后一次性自动登记通道 P。适用领域：学术科研类（数学/物理/生物医学/哲学社科/交叉学科）P0 必做；科技产业/财经时政类通常无预印本生态记 skip。工具用法见 `docs/TOOLS.md`「preprint_search.py」章节。

**校验规则**：素材库文件必须非空且含标题/公众号（或作者）/链接；若某通道零结果，改换关键词再试一次，仍无则记录"该通道无有效素材"。通道 E 素材（gathered_ima.md）条目须含 库名/标题/media_id，非空即计入有效通道。
**流转条件**：**适用通道全部执行完毕**后才可进入阶段 2——
- **必用通道**（E/A/B）：必须实际执行（E 未连接记跳过、A/B 零结果换词重试后记录），**禁止跳过或只做部分通道即开始写报告**；
- **必做通道（P0，按领域分档）**：F 查重 + B Web 为通用 P0（不分主题）；其余按领域矩阵——学术科研类 P 为 P0、A/C 为 P1/P2；科技产业类 C 为 P0、P 为 P2、A 为 P1；财经时政类 A/C 为 P0、P 为 P2。P0 通道缺失须补足，P1 零结果换词重试后记录"通道 X 无有效素材"，P2 记 skip。**禁止跳过 P0 通道即开始写报告**；finance 插件仍为按需（P1），未连接跳过不阻塞。
- 全部通道各自有结果记录（素材落盘或明确"无有效素材/不适用/跳过"）→ 汇总通道执行清单（F/E/A/B/C/P 各通道：命中 N 条 / 无素材 / 不适用）写入 plan.md → 进入阶段 2。
- **红线**：未完成全部适用通道前，不得产出 report.md。
- **落报告纪律**：通道"执行过 / 落盘素材"不等于"交付完成"。每个适用通道检索到的**硬数据（事实 / 数字 / 实体 / 结论）必须写入 report.md 正文相应小节**，与通道 A/B/P 同等对待；仅记录候选、仅标注"已检索"、或把检索结果"返回给用户看"而未写入报告正文，均视为该通道**未完成**，违反六通道 P0 必落报告的纪律。C 通道（企查查锁定的法人主体、通达信的上市 / 财务可核验性、智慧芽的专利布局数量）尤其易犯"只记录不落正文"的错，须逐一核对每条关键发现是否已进报告正文。
**通道完成态结构化登记**：每完成一个通道，须用 `python tools/mark_channel.py --slug <slug> --channel <F|E|A|B|C|P> --status <done|empty|skip> [--note ...]` 将其执行态写入 `research/<slug>/.progress.json` 的 `data.channels_done`（done=已执行有素材须有对应 gathered 文件；empty=已执行零命中也须记录"无有效素材"；skip=不适用/未连接须有 note 说明原因）。旧版的扁平 `channels:[...]` 列表不被任何门禁读取，视为无效。收尾门禁 `check_progress --require report_channels` 据此对六通道做「声明态 ⊕ 证据」双向交叉校验（声明缺失/证据缺失/有素材未登记/无 note 均阻塞），强制通道完成态可追溯、可核验。
**时限**：1–2 小时。

## 阶段 2 · 多视角信息收集

**执行者**：主代理（直执，subagent 当前不可用）；**输入**：素材库 + 检索记录；**输出**：五视角覆盖的原始发现清单。

主代理按五视角逐项收集：A 公众号观点、B Web 事实、C 领域分析、D 差异化（高赞/争议）、E 反方风险。每个视角至少一轮检索；关键子问题逐一覆盖不遗漏。
**校验规则**：五视角清单与阶段 0 界定的子问题逐一对照，有子问题未被任一视角覆盖即为缺陷。
**流转条件**：全部子问题均有素材覆盖 → 进入阶段 3。

## 阶段 3 · 交叉验证与量化

**执行者**：主代理；**输入**：五视角发现；**输出**：验证后的数据表（含数据级别标注）+ **量化测算（按需但必验，融入小节叙述）**。

- 每个关键数字标注数据级别（一手/二手/推断）；多源冲突以「最新 + 一手优先 + 口径一致」取舍。
- 媒体转述数字尽量回溯一手来源；无法取得的一律标"仅媒体口径"。
- 做**量化测算（按需但必验）**（市场规模/成本结构/情景推演/对比拆解/证明机制）：有计算价值的内容算式必须写、算式融入叙述；**禁止为凑数硬造算式，也禁止该写不写**（数学/证明类内容的机制算式是正文的一部分）；每条算式须经 Python 实际验证，验证脚本留存研究目录（如 `verify_calcs.py`）。对比/拆解/推演尽量移入测算展开，压缩「关键事实与数据」篇幅（**并列多条同类信息用有序列表 1. 2. 3. 组织、点数由内容自然决定**；小节数量不设上限）。
- **测算写法（按需但必验）**：每条测算含 假设前提 → 计算口径（**必含算式与数字**）→ 量化结果（**回引口径数字**）→ 口径说明（**含边界/敏感条件**）；quality_check 逐条检测（测算缺假设/无算式/结果未量化/缺口径说明）。**禁止为凑数硬造算式**——内容无需计算时不写测算；**数学/证明/机制类内容必须给完整论证链（定理-引理-证明或步骤归约），禁止只给方法名概述、禁止省略证明步骤**，来源论文的论证结构以论文全文（arXiv HTML 版）为准。
- 检查覆盖缺口：利益相关方、对标、风险矩阵是否完整。
**异常处理**：
- 数据不可得（如公告未公布细节）→ 标注"待正式公告"，用推断+区间呈现，不编造数字。
- 多源严重冲突 → 并列各方口径与来源，给取舍理由，不强行取一个。
**决策点（需用户审批）**：若关键数字缺失导致结论悬空，暂停并询问用户是否接受推断。
**流转条件**：量化测算完成且覆盖检查通过 → 进入阶段 4。
**时限**：2–3 小时。

## 阶段 4 · 报告生成与沉淀

**执行者**：主代理；**输入**：验证数据 + 量化测算；**输出**：report.md、process_notes.md、词库更新。

- 按 `templates/research_report_TEMPLATE.md` 产出 report.md（单章节两级层级：结论 → 关键事实与数据（小节内事实叙述+测算融入+分析表格）→ 参考文献）。
- 产出 `report.md`（过「数据可靠性」硬性自查，关键数字与来源一致）。
- **Word 导出**：交付前运行 `python tools/report_to_docx.py --slug <slug>` 生成 `report.docx`（图片从公网 URL 下载嵌入，与 report.md 同级）。
- **图文并茂**：交付前运行 `tools/report_images.py --slug <slug>` 生成配图——**AI 概念图仅作封面**（Agnes Image 2.1 Flash，$0/张，封面主视觉 `ai_cover.png`，独立存放不插入正文）+ **数据图表**（PIL/Pillow 绘制，弃用 matplotlib，价格/指数/成本对比等数字类图表，按内容锚点插入 report.md 对应小节）。**正文插图只用数据图表，AI 概念图不插入正文小节**；数据图表必须数字准确（不用 AI 生图）。**图片数量按内容需求而定，禁止无故生成**——每个锚点（小节）最多配 1 张图（anchor 须唯一，多图需锚点错开或人工在两图间补衔接文字）；**禁止两张图片连续**（两图间必须有文字内容）。**每张图必须带图注：`图 N｜说明（数据来源/口径）`，图号按出现顺序递增、封面不占号**——report_images.py 自动生成（caption 字段，缺省用 alt），数据图表图注须含数据来源；**AI 概念图禁止进正文**（封面仅作独立文件 ai_cover.png，正文插图只用数据图表；`quality_check check_cover_ban` 硬性拦截 ai_*.png 引用）。API key 走环境变量 `AGNES_API_KEY`，凭证不入库。
- **AI 概念图硬性禁元素（极其严格）**：封面/题图等所有 AI 生图必须为**纯抽象视觉**，严禁出现以下任何具象元素——(1) **任何语言文字**：汉字、英文、数字、字符、符号、logo、水印；(2) **任何徽章与国徽**：国徽、国旗、警徽、军徽、校徽、企业徽、盾牌纹章、奖章、勋章、任何带图案的圆形/盾形徽标；(3) **任何政府/司法/宗教建筑**：人民大会堂、政府大楼、法院、议会、教堂、寺庙、可识别的地标建筑；(4) **任何货币与票据**：钞票、硬币、债券、纸币、票据、发票、彩票、价格标签、收据；(5) **任何真实人脸与肖像**：清晰人脸、特定人物肖像、可识别名人；(6) **任何特定国家/政治符号**：国旗、政党标志、政治标语。**实现机制**：`tools/report_images.py` 的 `call_agnes` 在每个 prompt 末尾自动追加 `_AI_IMAGE_NEGATIVE_GUARD` 通用禁词句（含 "no text, no characters, no letters, no numbers..." 全套英文 negative）；每次生成封面后必须**肉眼检查**，若发现上述任一元素立刻删图重生成（不擅自保留），并在 `process_notes.md` 记录"封面图合规复检"。**检查清单见 `docs/CHECKLIST.md` AI 概念图合规复检项**。
- **AI 概念图主题相关性**：封面/题图等所有 AI 生图除合规外，**必须紧扣问题主题**——必须能在抽象视觉中映射问题的核心概念（如 LOF 退市→挤溢价泡沫+场内转场外；学术vs工业→书与机房的对话；半导体→晶圆/光刻意象）。**禁止使用与问题无关的纯装饰抽象图**（如"金色球体+棱柱"的通用科幻视觉，看似合规但读者看不出主题）。**实现方式**：写 prompt 时必须先提炼 2-3 个核心视觉符号（如"溢价泡沫→发光气泡群/退市闸口→几何门框/按净值赎回→规整立方体阵列"），再围绕这些符号构造抽象叙事场景（左→中→右的视觉过渡即可直观映射问题逻辑）；如当前 slug 复用通用 DEFAULT_AI_PROMPTS（"斩杀线"等旧模板），必须替换为当前主题专用 prompt（--ai-prompts 自定义 JSON）。**检查清单见 `docs/CHECKLIST.md` AI 概念图主题相关性复检项**。
- **AI 概念图构图饱满**：封面/题图**禁止大面积空白/留白**——prompt 一律不得出现"左下角留白适合叠加标题"等留白引导（标题由知乎发布时叠加，图内不留白）；画面构图必须饱满、平衡，视觉元素均匀铺满整个画布，边角不留白。`call_agnes` 的 `_AI_IMAGE_NEGATIVE_GUARD` 已含 "composition must be full and balanced, no large empty areas, no blank corners, no white space reserved for text overlay"；自定义 prompt 也不再写留白引导。生成后复检时同步检查构图（四角/边缘是否有大块均匀空白）。
- 写 process_notes.md：有效关键词与踩坑点（不做经验方法总结）。
- **沉淀（必做）**：有效关键词写入 SQLite 关键词库（`python tools/keywords_db.py --add ...`），再 `--export docs/KEYWORDS.md` 同步可读文件。
- **笔记上传 flomo（必做，不询问用户；上传「模块化笔记」，报告与索引禁止上传）**：`python tools/note_upload.py research/<slug>/notes/` 逐条质检后上传（00_index.md 与 report.md/report_draft.md 由工具自动拦截）；flomo 未配置时跳过并在 process_notes 记录，不阻塞交付。报告完整版如需本地存档，用 `tools/report_to_flomo.py --slug <slug> --out flomo_full.md` 仅生成 flomo 格式存档（不上传）。
- **公众号草稿推送（按需，用户指示时执行）**：`python tools/wechat_publish.py --slug <slug> --source-md`（环境变量 WECHAT_APPID/WECHAT_APPSECRET/WECHAT_AUTHOR）推送草稿箱 → 用户后台勾选原创声明/赞赏后发表（原创/赞赏 API 不支持，静默忽略；公式经 latex_unicode 转可读 Unicode 文本；详见 `docs/TOOLS.md`）。
- 回填本地 plan.md 索引状态为"已完成"。
**校验规则**：对 CHECKLIST.md 逐项自检，任何一项不通过即返回修正。**数据可靠性为硬性项**：关键数字必须可溯源；推断数字须标注"估算/推算"；媒体转述数字标注数据口径；不得用"据称/据说"式无出处引用。
**决策点（需用户审批）**：report.md 交付前由用户验收；用户有权要求修订。
**时限**：报告 2–3 小时（另含多轮迭代与用户验收）。

## 异常场景处理与回退机制

| 异常场景 | 检测信号 | 处理 | 回退路径 |
|---|---|---|---|
| 知乎页面 403/登录墙 | web_fetch 失败 | 请用户粘贴问题内容 | 回到阶段 0 |
| 公众号检索中文乱码 | 结果含乱码字符 | 用 wechat_search.py 文件传参 | 重试通道 A |
| ima 连接器未授权/不可用 | 通道 E 无结果或调用失败 | 跳过通道 E，不阻塞其余通道 | 降级（仅走 A/B/C/P 四通道） |
| 通道 C 必做项（通达信/企查查/智慧芽）连接器不可用 | 必做通道调用失败或返回空 | 记录"通道 C [数据源]未执行"告警，改用 Web/其余通道补位，不阻塞 | 通道 C 必做降级 |
| arxiv API 不可用/无网络 | 通道 P（arxiv 平台）调用失败或返回空 | 改用智慧芽（C）学术检索或 Web 补位，记录"通道 P 无有效素材" | 通道 P 降级 |
| E2 命中过多/返回过大 | 单库结果超限或超时 | 收窄到 2–3 个候选库、用更精确关键词重试 | E2 缩小范围 |
| 子代理不可用 | Model not found | 主代理直执 | 阶段 2 降级 |
| 关键数据缺失 | 核心结论无数据支撑 | 标注"待核实"+推断，必要时询问用户 | 阶段 3 暂停 |
| 报告被拒（AI 味/质量） | 用户反馈 | 按 STYLE_GUIDE 重写 | 阶段 4 重做报告 |
| 研究产出与已发布事实冲突 | 用户/交叉验证发现 | 更正数据并记录 | 阶段 3 重验 |
| 检索耗时超限 | 超过阶段时限 | 缩小范围、聚焦关键子问题 | 精简后继续 |

## 闭环管理与可追溯性

1. **追踪载体**：本地 `plan.md` 问题索引表记录每个问题的 日期/领域/slug/状态；状态机：规划中 → 进行中 → 已完成。
2. **变更留痕**：每阶段产出写入 `research/<slug>/` 对应文件，可逐文件回溯该问题完整研究过程。
3. **词库可追溯**：SQLite 关键词库新增词条记录回填来源问题（slug）；`docs/KEYWORDS.md` 仅作导出物。
4. **隐私边界**：research/、plan.md、.codebuddy/ 不纳入 git；提交由 pre-commit hook 自动拦截内部文件。
5. **发布审计**：所有对外（公开仓库）改动均有提交记录；涉及推送/强推/改可见性须用户审批并留痕。
6. **会话延续**：跨会话靠 `.codebuddy/memory/` 记录项目状态与用户偏好，新会话启动先跑 `python tools/health_check.py`。

## 质量红线

- 所有可量化数据必须有来源；无法核实的标注「未证实」。
- 不编造引用、不虚构数字、不替用户做决定（给权衡，不给单一路径）。
- 引用公众号文章须保留标题与作者信息。
- 报告须像真实从业者所写，无 AI 模板腔，按 `docs/STYLE_GUIDE.md`「去 AI 味」自查后发布。
- **报告为纯事实陈述**：不设结论、不表立场、不贴标签、不给建议、不替读者判断；立场中立为硬性检查项（见 CHECKLIST 与报告模板）。
- **报告禁止 A 股行情信息**：不得提及股票代号、股价、涨跌幅、总市值/PE 等 A 股行情字段（quality_check `check_stock_info` 拦截）；需产业背景时用公司名+产业事实表述。
- 未经用户明确同意，不执行推送、强推、改仓库可见性等操作。

# 执行级流程细化（附录 A）

> 本章将上文各阶段的"规范描述"细化为**可执行的判断逻辑**，明确每个步骤的输入/输出、判断分支、异常与边界条件、用户交互、触发条件与执行优先级。流程执行时以此章为准。

## A.0 通用约定

- **触发条件**：每个步骤标注「触发：xxx」。未满足触发条件不得进入下一步。
- **执行优先级**：标注 P0/P1/P2。P0=必须且最先（阻塞后续）；P1=必须（正常流程）；P2=可选优化。

 **通道优先级评定（按主题领域分档，替代一刀切 P0；工具化）**：
- **P0=该领域必做且最先**（缺失须补足或记录原因）；**P1=该领域应做**（无命中记"无有效素材"）；**P2=该领域可选**（通常无生态，可跳过或记 skip）。
- 领域分三档：**学术科研类**（数学/物理/生物医学/哲学社科/AI 理论等以论文为载体的主题）、**科技产业类**（AI 应用/半导体/机器人/3D 生成等前沿技术产业）、**财经时政类**（股票/宏观/政策/民生等）。
- **工具化**：`channel_state.classify_domain(domain)` 按关键词自动判定领域类型，`channel_plan(domain_type)` 输出通道优先级计划——`research_start.py` 初始化时自动调用并打印「领域判定 + 通道计划」，plan.md 的「领域档位」自动填充；config 可显式 `"domain_type": "学术科研|科技产业|财经时政"` 覆盖自动判定。
- **通用 P0（不分主题）**：F flomo 查重、B Web（一手来源优先）。
- 各领域通道优先级矩阵（F/B 均为 P0 不重复列出）：

| 通道 | 学术科研 | 科技产业 | 财经时政 | 说明 |
|---|---|---|---|---|
| P 预印本聚合（含 arxiv） | **P0** | P2 | P2 | 学术类论文为证据主体；产业/财经时政通常无生态记 skip |
| C 领域（通达信/企查查/智慧芽） | P1 | **P0** | **P0** | 学术类用智慧芽查专利/论文；产业/财经类通达信行情财务+企查查尽调为证据主体 |
| A 公众号 | P2 | P1 | **P0** | 财经时政的中文一手信源；产业类有科技媒体；学术类几乎无命中 |
| E ima | P1 | P1 | P1 | 连接器未配置时由初始化环境级自动登记 skip（`ZHIHU_ASK_UNCONFIGURED_CHANNELS` 可调）；已配置时按库检索 |
| finance 插件 | P2 | P2 | P1 | 财务建模按需，未连接跳过 |

- **评定依据**：学术主题（border blaster、QMC、量子游走、Borel–Cantelli 等）中 A 公众号与 C 领域几乎无命中而 P（arxiv/预印本）命中率高；财经主题（电力股、GLM 等）中 A/B/C 命中率高而 P 常空跑；E（ima）与 C（通达信/企查查/智慧芽）在本环境未配置，P0 名义与实际执行不符——重新评定后按领域如实标注。
- **执行纪律**：仍须登记全部六通道执行态（P0 缺失须补足、P1 无命中记"无有效素材"、P2 记 skip 即可），check_progress 完整性校验不变——优先级决定**执行强度**，登记完整性决定**纪律**。
- **交互格式**：主代理→用户用「待确认：问题」句式；用户→主代理用自然语言，主代理需解析为明确指令。
- **边界条件**：标注输入为空、超时、权限不足等极限情况下的行为。

## A.1 阶段 0 执行逻辑

**输入**：用户原始输入（问题文本/链接/空）。
**输出**：`plan.md` 问题界定完成 或 明确终止。

判断分支：
```
收到用户输入
├─ 输入为空 → 请求用户提供问题（P0），等待回复
├─ 输入为知乎链接 →
│   ├─ web_fetch 成功 → 提取标题/描述 → 进入拆解
│   └─ web_fetch 失败(403/登录墙) → 请用户粘贴标题或描述（P0，等待）
└─ 输入为问题文本 → 进入拆解
拆解完成
├─ 判断查询类型（深度/广度/直接）
│   ├─ 深度/广度 → 五视角覆盖（阶段 2 用）
│   └─ 直接 → 一轮检索即可（跳过阶段 2 的多视角收集）
└─ 定读者/篇幅 → 初始化 research_start.py
```

**边界条件**：用户 15 分钟未回复 → 暂停并告知"等待问题内容，恢复时继续"；问题明显超纲（政治敏感/违法）→ 直接拒绝并说明，不进入流程。
**用户交互**：
- 触发：会话开始或用户发来内容。
- 系统响应：受理后立即输出「已受理：<问题>，预计 <时限> 内完成」。
- 需用户输入：问题内容、问题类型确认（如可推断则自动判定）。

## A.2 阶段 1 执行逻辑

**输入**：plan.md 关键词表（须 ≥6 组，不足则补）。
**输出**：素材库非空 + 检索记录。

判断分支：
```
关键词表检查
├─ 关键词 <6 组 → 补足后再检索（P0）
└─ 关键词 ≥6 组 → 执行查重与检索通道
步骤0 flomo 查重（最先，阻断）
├─ flomo MCP 未配置/调用失败 → 阻断，禁止进入后续通道
├─ memo_search 搜问题主题词 → relevance ≥0.9（已有本主题笔记）
│   └─ 复用/更新已有笔记，不重复新建（结果记 plan.md）
├─ 0.5 ≤ relevance < 0.9 → 正常检索通道（flomo 条目按「flomo 笔记素材引用规则」判断可用性：有合规 GB/T 参考文献即可作素材）
└─ <0.5 → 正常检索通道
检索通道执行（F 查重后 E 最先）
├─ 通道E(ima): 两级检索
│   ├─ ima 连接器未连接 → 跳过，不阻塞其余通道
│   ├─ E1 经验检索: search_knowledge_base 定位库 → 个人库 search_knowledge
│   │   ├─ 命中 → 片段纳入检索起点（与本地 rag_search 互补）
│   │   └─ 无命中 → 记录"E1 无有效素材"
│   └─ E2 内容素材检索: 按领域取 IMA_LIBRARIES.md 候选库（取全）→ 逐库 search_knowledge
│       ├─ 命中 → 落盘 gathered_ima.md（库名/标题/类型/media_id），计入有效通道
│       ├─ 无命中 → 每库换关键词重试（≥2 个关键词）→ 全部候选库+全部词仍无 → 记录"通道 E 无有效素材"
│       └─ 命中过多 → 收窄库范围或更精确关键词重试
├─ 通道A(公众号): wechat_search --output 落盘（优先级按领域：财经时政 P0 / 科技产业 P1 / 学术科研 P2）
│   ├─ 素材库为空 → 换关键词重试1次 → 仍空则记录"该通道无有效素材"
│   └─ 非空 → 通过
├─ 通道B(Web): 检索官方/研报/新闻，优先一手（P0，不分主题）
├─ 通道C(插件/连接器): 通达信(tdx-connector)、企查查(qcc-company)、智慧芽(patsnap-search)（按领域：科技产业/财经时政 P0、学术科研 P1；通达信查行情·财务、企查查锁企业实体、智慧芽专利+论文各一次调用）；finance 插件按需
│   ├─ 必做项未连接/返回空 → 记录"通道 C [数据源]未执行"告警，改用 Web 补位（不阻塞）
│   └─ 有结果 → 按工具纪律使用（通达信 code 先 lookup；企查查先 by_query 锁定实体；智慧芽 strategy 与参数严格绑定）
├─ 通道P(学术预印本聚合, 含 arxiv): tools/preprint_search.py --platform all --keywords "<query>"（按领域：学术科研 P0 / 科技产业·财经时政 P2；arxiv→gathered_arxiv.md、其余三平台→gathered_preprints.md，同属通道 P）
│   ├─ 命中 → 落盘 gathered_arxiv.md（标题/作者/日期/摘要/arxiv 链接/PDF），计入有效通道
│   └─ 无命中/API 不可用 → 换关键词重试 1 次 → 仍无则记录"通道 P 无有效素材"（改用智慧芽/Web 补位）
汇总
├─ 有效通道 ≥2 → 进入阶段 2
└─ 有效通道 <2 → 补充检索（P1），仍不足则告知用户并降级（以 1 通道完成）
```

**边界条件**：公众号接口失败（验证码/反爬）→ 记录并转 Web 通道为主，不阻塞；全部通道失败 → 终止并告知用户"当前无法获取有效信源"。
**用户交互**：无主动交互；若通道降级需在最终交付物中注明"信源受限"。
**优先级**：步骤 0 flomo 查重 P0（**执行顺序最先**，防重复研究；未配置时跳过不阻塞），F 查重与 B Web 为通用 P0；其余按领域矩阵——学术科研：P P0、C P1、A P2；科技产业：C P0、P P2、A P1；财经时政：A/C P0、P P2。E（ima）未配置记"通道 E 未连接"跳过不阻塞，P2 通道记 skip，P1 无命中如实记录"无有效素材"。

## A.3 阶段 2 执行逻辑

**输入**：素材库 + 检索记录。
**输出**：五视角原始发现清单（A 公众号观点 / B Web 事实 / C 领域分析 / D 差异化 / E 反方）。

判断分支：
```
子问题清单（阶段0定义）与五视角对照
├─ 某子问题无任何视角覆盖 → 补检索该子问题（P0）
│   ├─ 补后仍无 → 记录"该子问题无公开素材"，结论中标注
│   └─ 补后有 → 通过
└─ 全部覆盖 → 通过
```

**边界条件**：查询类型为"直接查询"→ 跳过本阶段，由阶段 1 素材直接进入阶段 3。
**用户交互**：无。
**优先级**：先覆盖 P0 子问题（决定报告骨架的），再覆盖 P1（补充性），P2（加分项）。

## A.4 阶段 3 执行逻辑

**输入**：五视角发现。
**输出**：数据表（含数据级别）+ 量化测算（**按需但必验，禁止凑数也禁止该写不写**）。

判断分支：
```
数据整理
├─ 关键数字无来源 → 标注"未证实"（P0），后续回溯
│   ├─ 能回溯到一手 → 更新为一手
│   └─ 无法回溯 → 保留"仅媒体口径"标注
├─ 多源冲突 → 并列各方口径+来源，按"最新+一手优先+口径一致"取舍
├─ 关键数字缺失导致结论悬空 →
│   ├─ 可推断 → 用区间+假设呈现，标注"推断"
│   └─ 不可推断 → 暂停，向用户确认（P0 决策点）
└─ 量化测算
    ├─ 有计算价值的内容 → 写入算式（融入叙述）
    └─ 无计算价值/数据不足 → 不写测算，说明原因+给替代可观察指标
```

**决策点（用户审批）**：仅在"结论悬空且无法推断"时触发，向用户说明缺口与选项。
**边界条件**：所有关键数据均缺失 → 终止研究并告知用户"该问题当前无可靠公开数据支撑报告"。
**用户交互**：决策点询问时用户可选「接受推断 / 更换问题角度 / 终止」。

## A.5 阶段 4 执行逻辑

**输入**：验证数据 + 量化测算。
**输出**：report.md / process_notes.md / 词库更新 / 索引回填。

判断分支：
```
生成报告 → 自检（CHECKLIST）
├─ 任一项不通过 → 返回修正对应环节
└─ 全部通过 →
    ├─ 用户验收（P0 决策点）
    │   ├─ 通过 → 交付
    │   ├─ 需重写（AI味/质量） → 按 STYLE_GUIDE 重写后重新提交验收
    │   └─ 需补充 → 补充后重新提交
    └─ 沉淀（必做）
        ├─ 有效关键词写入 SQLite 关键词库（P0），再 --export docs/KEYWORDS.md
        ├─ process_notes.md 完成（P0）
        ├─ plan.md 索引回填"已完成"（P0）
        └─ 笔记上传 flomo（P0，不询问）：note_upload.py notes/ 逐条质检后上传；索引/报告禁止上传；flomo 未配置则跳过并记录
```

**边界条件**：用户 24 小时未验收 → 再次提醒；仍未回复 → 交付物保留在工作区，待用户随时查看。
**用户交互**：
- 触发：交付完成。
- 系统响应：输出交付物路径 + 关键结论摘要。
- 需用户确认：验收通过/需修改，或对结论有异议。

## A.6 全局异常与回退优先级

异常处理统一规则（与上文异常表配套，此处给执行顺序）：

1. 检测异常 → 判断严重度（阻断/非阻断）
2. 阻断级（数据全缺失、信源全失败、权限问题）→ 立即暂停，向用户说明（P0）
3. 非阻断级（单通道失败、子问题无素材、报告需重写）→ 降级继续，最终交付物中注明（P1）
4. 回退遵循"就近回退"：优先退回上一阶段修正，不跨多阶段重启

## A.7 流程闭环与执行顺序总览

```
用户提问 → A.1(阶段0) → A.2(阶段1) → A.3(阶段2) → A.4(阶段3) → A.5(阶段4) → 用户验收 → 沉淀 → 闭环
     ↑          ↑            ↑            ↑            ↑            ↑
     └─ 每阶段不满足输出条件即回退到该阶段开头重做，满足才向下流转
```

执行顺序规则：阶段串行，P0 优先；任一阶段输出未达校验规则即阻塞后续阶段（不进不退）。

**进度校验工具化**：`research/<slug>/.progress.json` 由 `tools/init_research.py` 在阶段 0 初始落盘（含 `round=1` 与 `domain`），`tools/research_start.py` 在阶段 0/1 完成后合并更新（保留 `round`，不覆盖）。进入阶段 2 前用 `python tools/check_progress.py --slug <slug> --require phase1_done` 校验前置就绪（通过退出码 0，阻塞退出码 1），把"输出未达校验即阻塞"从文档约束落地为工具强制。

## A.8 多轮迭代研究（强制，默认 1 轮，有未解决内容则追加）

**多轮迭代为可选深化机制：默认 1 轮成稿；仅当一轮存在无法解决的内容时才追加轮次，且不得询问用户是否继续。**

**最低轮次**：

| 领域 | 最低轮次 | 说明 |
|---|---|---|
| 所有领域（财政/宏观/金融/AI/数码/能源/科技战略/营销等） | 1 轮 | 默认 1 轮成稿：一轮完成骨架+定稿+质检的最低深度 |
| 一轮存在无法解决的内容时 | 追加至问题清单清空 | 一轮后若有"仍无法核实/推算"或口径缺口，追加轮次处理，直至问题清单清空 |

**机制**：`python tools/iter_research.py --slug <slug>` 生成下一轮问题清单模板（写 round_notes.md；历史轮次自动归档为 `round_notes_r<N>.md`，保留可追溯）并更新 `.progress.json` 的 round 记录；工具按 `.progress.json` 的 `domain` 字段自动提示当前轮次与领域最低轮次（未达标显示还需 N 轮）。达标校验：`python tools/check_progress.py --slug <slug> --require_round auto`（auto 按领域自动判定，阻塞时退出码 1）。问题清单由主代理人工编写：阅读报告中标注"仍无法核实/推算"的内容与数据口径缺口，逐条整理成明确、可执行的问题。不用自动提取——机械拆句语义不清，人工整理才可靠。

**强制流程（默认 1 轮，不询问用户）**：
- 第 1 轮：research_start.py 启动 → 阶段 2/3/4 → 产出 report.md → 质检八件套通过（结构/质量/去 AI 腔/国标/违规引用/矛盾/轮次/落报告）。
- 追加轮次条件（满足任一即进入第 2 轮）：①报告存在"仍无法核实/推算"的内容；②存在数据口径缺口未澄清；③质检拦截项需补检索才能修复。跑 iter_research.py 生成问题清单模板 → 人工填写未尽问题 → 带着问题补检索/深化 → 直接在 report.md 上更新。
- 追加轮次直至问题清单清空（每轮处理上一轮 round_notes.md 中的问题）。

**执行规则**：
- 默认 1 轮交付：一轮后问题清单已清空（无"仍无法核实"内容、无口径缺口、质检通过）即研究完成，**禁止无谓追加轮次**。
- 追加轮次时：每轮必须处理上一轮 round_notes.md 中的问题；若问题清单仍有未处理内容，必须继续后续轮次，直到问题清单处理完为止。
- 无法补足的问题标注"仍无法核实"后从问题清单移除。
- 报告在 report.md 上直接更新，不创建 vN 版本文件；深化过程记录于 process_notes.md。
- **报告必须是成品**：正文禁止出现"第 N 轮/迭代/更新"等过程性字样，任何时点报告都可作为最终成品直接使用；过程记录只存在于 process_notes.md 与 round_notes.md。
- 追加轮次不得以"已收敛"为由提前停止；问题清单已清空且边际收益显著下降，方可停止。

**质量增益**：多轮让数据从"二手转述"回溯到"一手来源"、让推断从"无标注"变成"有口径"，报告随轮次深化而更扎实。
