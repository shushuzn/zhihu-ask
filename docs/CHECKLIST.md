# 发布前质量检查清单

阶段 4 完成后、回答发布前，逐项核对。分「研究质量」与「回答质量」两组，任何一项不满足则返回修正。

## 研究质量

- [ ] 每个可量化数据（数字、百分比、金额、日期）都有来源链接。
- [ ] 每个关键数字标注数据级别（一手/二手/推断）。
- [ ] 媒体转述数字已尽量回溯一手来源；无法取得的一律标注「仅媒体口径」。
- [ ] 多源冲突的数据已标注并说明取舍依据。
- [ ] 无法核实的内容标注「未证实」，未被当作事实输出。
- [ ] 公众号引用保留「公众号名 + 文章标题 + 链接」。
- [ ] 关键结论至少被两个独立来源交叉印证（公众号/Web/插件任意组合）。
- [ ] 反方观点或风险提示已覆盖（针对有争议或涉及风险的议题）。
- [ ] 至少完成一项量化测算（市场规模/成本结构/情景推演），非形容词式判断。
- [ ] 利益相关方矩阵、对标比较、风险矩阵已覆盖（针对多维影响问题）。

## 回答质量（纯事实陈述）

- [ ] 开头直接进入事实（事件/数据/背景），无"结论先行"。
- [ ] 全文至少一处具体数字或可验证事实作为记忆点，且带来源与口径。
- [ ] 段落 ≤ 4–5 行，每段一个事实点；标题像事实目录。
- [ ] 对比类内容使用表格，表前说明口径、表后客观解读（不夹评价）。
- [ ] 至少 1 处结构性拆解（归因/构成/成本拆分），推算已标注"推算"与口径假设。
- [ ] 至少 1 处对照数据（历史/行业/国际）。
- [ ] 涉及理财、投资、医疗、法律等给出风险提示与免责声明。
- [ ] 无 emoji、无多余分隔线；Markdown 可直接粘贴知乎。
- [ ] 去 AI 味（对照 STYLE_GUIDE）：无框架词（先说结论/总结一下）、无"其一其二"、无感叹号/反问句、数字嵌叙述。

立场中立（硬性，发布前必须全部通过）：
- [ ] 无"我认为/我的判断/结论很硬/显然/可见/证明"等立场词。
- [ ] 无评价性形容词（太猛/很差/厉害/离谱）与贴标签。
- [ ] 无"应该/不该/建议/最好"式价值建议。
- [ ] 无"总之/所以结论是"式总结判断。
- [ ] 判断权完全留给读者。
- [ ] 已运行 `python tools/quality_check.py --file <回答>`，检出项已人工确认（未误杀合法用法）。
- [ ] 参考文献为纯链接列表（`[标题](url)`），无"一手/二手/推断"等分级标注（分级只在正文）。

数据可靠性（硬性，发布前必须全部通过）：
- [ ] 每个关键数字可溯源（正文或脚注给出来源），无一问三不知的数字。
- [ ] 推断/估算数字已明确标注"估算/推算"，未伪装成精确事实。
- [ ] 媒体转述的敏感数字标注了数据口径（如"展示产品口径"）。
- [ ] 全文无"据称/据说/传闻"式无出处引用。
- [ ] 无法核实的关键数据已明确说明或删去，而非含糊带过。

## 发布前终审（最后一关，全部通过才可发布）

- [ ] 全文数字自洽：同一指标在文中出现的数值一致，无前后矛盾。
- [ ] 若含结论，结论与论据匹配；若无结论，确认未下结论（保持中立）。
- [ ] 逻辑无漏洞：无跳步（A→B 缺中间）、无因果颠倒、无双标。
- [ ] 删冗余：已去掉重复观点、无关信息、凑字数段落。
- [ ] 反问视角自查：以"最挑剔的读者"身份重读，挑出的任何存疑点已处理。
- [ ] 若涉及投资/风险，风险提示已覆盖关键下行风险，非仅正面叙事。

## 发布后

- [ ] `process_notes.md` 已写入：有效关键词、踩坑点。
- [ ] `process_notes.md` 的有效关键词已回填至 `docs/KEYWORDS.md`（沉淀必做）。
- [ ] 本地 `plan.md` 问题索引状态已更新为「已完成」。
- [ ] 如模板或 SOP 需要调整，已同步更新 `templates/`、`docs/SOP.md`、`docs/TEMPLATE_INDEX.md`。
